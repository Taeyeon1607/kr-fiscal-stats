
# KOSIS 통계 받아오기 — 국세통계 특화

KOSIS 공유서비스(OpenAPI)로 **통계표를 찾고 → 자료를 받는다.**
**국세통계는 목록을 통째로 들고 있어서 찾는 단계를 건너뛸 수 있다.**

---


## 1. 국세통계는 이렇게 — **찾을 것 없이 바로 표번호를 집는다**

`references/` 에 국세통계 **1,258개 표**가 분류별로 들어 있다.

| 파일 | 무엇 | 개수 |
|---|---|---|
| `kosis-국세통계-최근.md` | **지금 쓰는 것.** 2011년 이후 체계 | **574** |
| `kosis-국세통계-2010이전.md` | 옛 체계(1966~2010). 장기 시계열을 볼 때 | **684** |

★목록은 받은 날의 것이다 — 목록에 없는 표를 찾거나 `err 21 해당 통계표가 존재하지 않습니다` 가 나면
`python3 scripts/kosis.py 대조` 로 지금 KOSIS 와 맞춰 본다(1분쯤). 달라졌으면 `대조 --고치기` 로 두 목록 파일을 새로 쓴다.

**국세청 기관번호는 언제나 `133`.** 표번호는 `DT_13301_000`·`TX_13301_A056` 꼴이다.

자주 찾는 것 몇 개(최근분 「총괄」):

| 표번호 | 이름 |
|---|---|
| `DT_13301_000` | 1.1 국세청 소관 세수 현황[1966~] |
| `TX_13301_A056` | 1.2 국세 징세비 현황[1980~] |
| `TX_13301_A009` | 1.3 세목별·지역별 납세인원 현황[2005~] |

분류 가지는 **총괄 · 징수 · 종합소득세 · 원천세 · 양도소득세 · 상속·증여세 · 종합부동산세 · 법인세 ·
부가가치세 · 소비제세 · 주세 · 국제조세 · 근로·자녀 장려금 · 세무조사 · 기타** 로 나뉜다.

```bash
# 국세통계 최근분의 가지를 훑어보기
python3 scripts/kosis.py list 133_13301_200
# 그 아래 「총괄」의 표들
python3 scripts/kosis.py list 133_13301_200_10
```

---

## 2. 국세통계 밖의 것은 **낱말로 찾는다**

KOSIS 전체(29만 표)를 낱말로 뒤진다.

```bash
python3 scripts/kosis.py search "사업체 종사자"
python3 scripts/kosis.py search "장래인구추계" --개수 20
```

결과에 **기관번호 · 표번호 · 표 이름 · 분류 경로 · 자료 기간**이 함께 나온다.
그대로 3절의 `data` 에 넣으면 된다.

★**찾기 요령** — 낱말을 **짧게** 쓴다. 문장으로 넣으면 0건이 나온다.
「경기도 시군별 사업체 수 2023」 ❌ → 「사업체」 ⭕ 로 찾고 분류 경로를 보고 고른다.

---

## 3. 자료 받기

```bash
# 최근 5개 기간
python3 scripts/kosis.py data 133 TX_13301_A056 --최근 5

# 기간을 찍어서 + csv 저장
python3 scripts/kosis.py data 133 DT_13301_000 --기간 2018 2024 --csv 세수.csv

# 분기·월 자료
python3 scripts/kosis.py data 101 DT_1J22042 --주기 Q --최근 8
```

| 인자 | 뜻 | 기본 |
|---|---|---|
| `--주기` | `Y` 해 · `Q` 분기 · `M` 달 | `Y` |
| `--최근 N` | 최근 N개 기간 | 5 |
| `--기간 시작 끝` | 예: `--기간 2018 2024` | — |
| `--항목` | 항목 코드. 보통 `ALL` | `ALL` |
| `--분류1`, `--분류더` | 분류 코드. 보통 `ALL` | `ALL` — ★분류가 두 겹 이상인 표는 **스크립트가 알아서 겹을 더한다**(함정 ③) |
| `--csv` | csv 로 저장 | — |

★**받은 자료에는 `C1_경로`·`C2_경로` 칸이 붙는다** — 그 칸의 **윗 분류까지 이은 이름**이다
(`과년도분 > 내국세 > 직접세 > 소득세` · `중부청 > 경기`). **값을 고를 때는 `C1_NM` 이 아니라 이 칸을 본다**(함정 ⑦).

## 4. ★반드시 알고 시작할 함정 (전부 실제로 재 본 것)

### ① HTTP 는 언제나 **200** 이다 — 오류도 200 으로 온다

본문이 `{"err":"11","errMsg":"유효하지 않은 인증KEY입니다."}` 꼴이면 실패다.
**상태코드만 보고 성공으로 넘기면 안 된다.** (스크립트가 가려 준다.)

### ② ★**통계목록 API 의 키 오류는 «깨진 JSON» 으로 온다**

`{err:"11",errMsg:"…"}` — **키에 따옴표가 없다.** 그냥 파싱하면 그 자리에서 죽는다.
같은 오류인데 **자료 API 는 멀쩡한 JSON** 으로 준다. 창구마다 다르다.
(스크립트가 고쳐 읽는다. 직접 부를 때는 조심한다.)

### ③ ★분류가 **몇 겹인지**만큼 `objL` 을 줘야 한다 — 표마다 다르다

`itmId`·`objL1` 은 언제나 필수이고, **분류가 두 겹인 표는 `objL2` 도, 세 겹이면 `objL3` 도** 줘야 한다.
모자라면 `err 20 필수요청변수값이 누락되었습니다. (objL)`, **넘치면 `err 21`** 이다.
국세통계는 **두 겹짜리가 흔하다**(시험한 네 표 중 셋 — 지역별 세수·확정신고 인원·법인세 신고 현황).
⟹ **스크립트는 `err 20 (objL)` 이 나면 `ALL` 을 한 겹씩 더해 다시 부른다.** 직접 부를 때는
`objL1=ALL&objL2=ALL…` 을 하나씩 늘려 가며 `err 20` 이 사라지는 곳을 찾는다.

### ④ ★★**단위가 «항목마다» 다르다**

같은 표 안에서 국세청세수는 **억원**, 징세비는 **백만원**, 정원은 **명** 이었다(실측).
⟹ **표 하나에 단위 하나라고 가정하면 숫자가 통째로 틀린다.**
칸마다 `UNIT_NM` 을 보고, **합치거나 비율을 낼 때 단위를 먼저 맞춘다.**
스크립트는 단위가 둘 이상이면 경고를 낸다.

### ⑤ ★**쪽 넘김이 없다 — 「다 받았다」를 확인할 길이 없다**

이 창구는 한 번 부르면 그것으로 끝이고, **상대가 상한에서 잘라도 그 사실을 알려 주지 않는다.**
⟹ **기간·분류를 좁혀 나눠 받고**, 받은 칸 수가 기대와 맞는지 **스스로 따져 본다**
(예: 5년 × 17개 시도 × 3항목 = 255칸). 수가 어중간하게 떨어지면 잘린 것을 의심한다.

### ⑥ 큰 표는 한 번에 다 오지 않는다

분류가 여러 겹인 표는 칸이 수만 개가 된다. **기간을 좁히고**(`--기간`),
분류를 하나씩 지정해 나눠 받는다. 한 번에 다 받으려 하지 않는다.

### ⑦ ★★**같은 이름이 여러 층에 나온다 — 이름으로 고르면 합계를 잘못 집는다**

「2.1.2 연도별·세목별 세수」에는 `소득세` 가 **세 번** 나온다 — 국세청 세수 아래, **현년도분** 아래,
**과년도분** 아래. 셋 다 `C1_NM` 은 `소득세` 이고 분류 이름(`C1_OBJ_NM`)도 「세목별」 하나뿐이다.
⟹ **스크립트가 붙이는 `C1_경로` 칸으로 가른다**(`국세청 세수 > 내국세 > 직접세 > 소득세`).
합계 행도 표마다 **`합 계`(띄어 씀)와 `합계`** 가 섞여 있다 — 이름으로 거르지 말고 경로를 본다.

### ⑧ ★★**지역 축은 «지방국세청»이다 — 시도가 아니다**

지역별 표의 지역은 `서울청·중부청·인천청·대전청…` 이고 **시도는 그 아래에 들어 있다.**
**경기는 `중부청 > 경기` 와 `인천청 > 경기` 두 곳**에 나뉘어 잡힌다(2025년 세수 46.1조 + 11.9조).
「서울」 행은 없고 `서울청` 만 있다.
⟹ **시도 비중을 낼 때는 같은 시도 이름의 행을 «경로로 확인하고» 더한다.** 한 행만 집으면 경기를
절반 가까이 빠뜨리고, 지방청 행까지 더하면 두 번 센다. **더했으면 더했다고 밝힌다.**

## 5. 오류 코드

| 코드 | 뜻 | 할 일 |
|---|---|---|
| `11` | 인증키가 유효하지 않음 | 키 확인. 신청 직후면 승인까지 기다린다 |
| `20` | 필수 변수 누락 | `(objL)` 이 붙어 있으면 분류 겹이 모자란 것 — **스크립트가 알아서 더한다**(함정 ③) |
| `21` | 「해당 통계표가 존재하지 않습니다」 | 표번호 오타. 목록 파일이나 `search` 로 다시 찾는다 |
| `21` | 「잘못된 요청 변수를 호출 하였습니다」 | **분류를 표보다 많이 줬거나, 분류 «값»이 틀렸다**(수원시를 `31010` 으로 짐작 → 실제 `41110`). 분류를 `ALL` 로 받아 이름으로 찾는다 |

★**1인당 값의 분모(인구)는 시점을 밝힌다** — 주민등록인구 연말 값인지 연앙인지, 몇 년 것인지 적는다.

★결과가 **빈 배열**이면 오류가 아니라 **그 조건에 자료가 없는 것**이다. 기간을 넓혀 본다.

## 6. 일하는 순서

1. **사용자 말에서 「무슨 통계 · 어느 기간 · 어느 단위(전국/시도/시군구)」를 뽑는다.** 빠진 것은 묻는다.
2. **국세 관련이면** `references/` 목록에서 표번호를 집는다. 아니면 `search` 로 찾는다.
3. **먼저 `--최근 3` 으로 조금만 받아 본다.** 칸 이름 · 분류 · **단위**를 여기서 확인한다.
4. 맞으면 **기간을 넣어 본 호출**, `--csv` 로 저장한다.
5. **받은 뒤 눈으로 확인한다** — 기간이 맞는지, 단위가 섞이지 않았는지, 빠진 해가 없는지.
6. 사용자에게 줄 때 **출처와 받은 날**을 적는다 — 「KOSIS 국가통계포털, 국세청 국세통계, 2026-09-21 받음」.

---

## 7. 하지 않을 것

- **없는 값을 지어내지 않는다.** 빈 결과는 「그 조건에 자료가 없다」고 말한다.
- **단위를 짐작해 환산하지 않는다.** 억원·백만원·천원이 한 표에 섞여 있다(함정 ④).
- **표 이름만 보고 내용을 단정하지 않는다.** 「[1966~]」처럼 기간이 이름에 붙어 있고,
  **최근분과 2010년 이전분은 체계가 달라 그대로 이어 붙이면 안 된다.**
- **합계를 직접 더했으면 더했다고 밝힌다.** 표에 든 합계 행과 섞지 않는다.
- 한 번에 수십 표를 훑지 않는다. 필요한 것부터 하나씩.
