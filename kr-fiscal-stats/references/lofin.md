
# 지방재정365 자료 받아오기

행정안전부 지방재정365가 공개하는 **146종의 자료**를 API 로 받아 온다.
쓰는 사람은 「무슨 자료가 필요한지」만 말한다. **자료코드를 찾고 인자를 맞추는 것은 이 문서가 시킨다.**

---


## 1. 부르는 법

```
GET https://www.lofin365.go.kr/lf/hub/{자료코드}
    ?Key={인증키}&Type=json&pIndex={쪽번호}&pSize={쪽당건수}&{거르개...}
```

| 인자 | 뜻 | 비고 |
|---|---|---|
| `Key` | 인증키 | 필수 |
| `Type` | `json` | ★**빼면 XML 로 온다.** 반드시 넣는다 |
| `pIndex` | 쪽 번호(1부터) | 기본 1 |
| `pSize` | 쪽당 건수 | 기본 100, **최대 1000** |
| 그 밖 | 거르개(연도·자치단체 등) | 자료마다 다르다. 2절 참고 |

**성공 응답 모양** — 최상위 키가 «자료코드»다.

```json
{ "RHJDKD": [
    { "head": [ {"list_total_count": 486},
                {"RESULT": {"CODE":"INFO-000","MESSAGE":"정상 처리되었습니다."}} ] },
    { "row": [ {"fyr":"2024","laf_cd":"1100000","laf_hg_nm":"서울본청", ...}, ... ] } ] }
```

---

## 2. ★반드시 알고 시작할 함정 (전부 실제로 재 본 것)

### ① HTTP 상태는 «언제나 200» 이다 — 성공 여부는 본문에서 본다

키가 틀려도 200, 자료코드가 틀려도 200 이 온다.
**`RESULT.CODE` 를 봐야 한다.** 상태코드만 보고 「성공」으로 넘기면 빈손으로 한참 간다.

### ② 실패·빈결과는 **모양이 다르다**

성공은 `{"자료코드": [...]}` 인데, 실패와 「자료 없음」은 `{"RESULT":[{...}]}` 이다.
**같은 방식으로 파싱하면 깨진다.** 먼저 `"RESULT" in 응답` 인지 본다.

### ③ **모르는 인자는 조용히 무시된다**

`zzz=1` 같은 엉뚱한 인자를 줘도 오류가 안 나고 **전체 건수가 그대로 온다.**
⟹ **거르개 이름을 틀리면 「거르개가 안 먹었다」가 아니라 「전부 다 받았다」가 된다.**
거르개를 넣었으면 **총건수가 줄었는지 반드시 확인한다**(예: 486 → 243).

### ④ 많은 자료가 **연도(`fyr`)를 필수로 요구한다**

연도를 안 주면 `ERROR-300 필수 값이 누락되어 있습니다`.
**그런데 무엇이 필수인지 오류가 말해 주지 않는다.**
⟹ **ERROR-300 이 나오면 먼저 `fyr`(회계연도)을 넣어 본다.** 대부분 이걸로 풀린다.

### ⑤ ★**비슷한 자료가 «당초·최종·결산» 셋으로 나뉘어 있다**

재정자립도만 해도 `DCFCE`(당초) · `JFIED`(최종) · `FNCST`(결산) 셋이다. 값이 서로 다르다
(수원시 2024 자립도: 당초·결산이 다르다). 이름 끝의 `[당초]`·`[최종]`·`[결산]` 을 보고 고른다.
- **당초** = 그해 처음 세운 예산 기준. 올해·내년 자료가 있다
- **최종** = 추경까지 반영한 예산 기준
- **결산** = 실제로 쓴 뒤의 값. **한두 해 늦게 나온다**
⟹ **사용자가 안 정했으면 묻는다.** 모르면 「지난해까지는 결산, 올해는 당초」가 무난하다. **어느 것을 썼는지 밝힌다.**

### ⑥ ★**한 행이 «자치단체 하나»가 아니다 — 더해야 표가 된다**

`AIDFA`(구조별 기능별 세출예산) 같은 자료는 한 행이 **회계 × 분야 × 부문** 하나다.
경기 시군 2025 은 **1,642행**이 온다. 「시군 × 분야」 표를 만들려면 묶어서 더해야 한다.
⟹ 스크립트의 `--sum 금액칸 --by 묶을칸` 을 쓴다(7절). **더한 값이라고, 어느 칸을 더했는지 밝힌다.**
★`…_tott_amt`(총계)는 회계 사이 내부거래를 포함한다. 회계를 넘어 더하면 `…_prsm_amt`(순계)와 달라진다 — 어느 쪽을 썼는지 적는다.

### ⑦ ★★**칸 이름이 번호형이다 — 뜻은 `references/lofin-칸뜻.md` 에서 본다**

`IIBBH`(세입결산)는 `total · pfa_amt1 · pfa_amt2 · pfa_amt3 · pfa_amt4` 로 온다. 이름만으로는 무엇인지 모른다.
포털의 자료별 「출력값」 표를 146종 전부 옮겨 둔 것이 `references/lofin-칸뜻.md` 다(`pfa_amt1` = 일반회계 … `pfa_amt4` = 기금).
**`--peek` 가 칸 이름 옆에 뜻을 같이 찍어 준다.**
★**순서로 맞추지 않는다** — 포털 표와 실제 응답의 칸 순서가 다른 자료가 있다. 이름으로 맞춘다.
(예: `IIBBH` 는 포털 표 맨 앞이 `pfa_amt4` 다.)
★**칸 이름의 글자로 뜻을 짐작하지 않는다** — 이름과 뜻이 엇갈리는 칸이 있다(`AIDFA` 의 `fin_acv_*` = 행정운영경비). 칸뜻 표를 본다.

### ⑧ ★★**금액 단위가 거의 안 적혀 있다**

146종 중 **단위를 적어 둔 것은 8종뿐**이다(칸 뜻에 `(천원)`·`(원)` 이 붙은 것). 나머지는 공식 표기가 없다.
시험해 본 자료(세입결산·세출예산·재정자립도의 자체수입·현금성복지비)는 **원 단위**로 보인다
— 의정부시 2024 세입결산 총계 1,751,914,749,350 = 약 1.75조. **크기로 맞춘 추정이다.**
⟹ **단위를 단정하지 않는다.** 칸 뜻에 단위가 없으면 알려진 규모 하나와 맞춰 보고,
사용자에게는 「단위 표기가 없어 크기로 추정(원)」이라고 함께 적는다.

### ⑨ `pSize` 는 1000 이 천장

1000을 넘기면 `ERROR-336 데이터요청은 한번에 최대 1,000건을 넘을 수 없습니다`.
그보다 많으면 `pIndex` 를 올려 가며 여러 쪽을 받는다. 범위를 넘은 쪽은 `INFO-200`(자료 없음)이 온다.

## 3. 응답 코드

| 코드 | 뜻 | 할 일 |
|---|---|---|
| `INFO-000` | 정상 | — |
| `INFO-200` | 해당 자료 없음 | 오류가 아니다. 거르개(연도·지역)를 넓힌다 |
| `ERROR-290` | 인증키가 유효하지 않음 | 키 확인. 승인 전이면 기다린다 |
| `ERROR-300` | 필수 값 누락 | **`fyr` 부터 넣어 본다**(함정 ④) |
| `ERROR-310` | 해당 서비스 없음 | 자료코드 오타. `references/lofin-목록.md` 에서 다시 찾는다 |
| `ERROR-336` | 1회 1,000건 초과 | `pSize` 를 1000 이하로 |

## 4. 어떤 자료가 있는지 찾는 법

<HARD-GATE>
★**자료 API(`/lf/hub/…`)에는 목록을 주는 이름이 없다** — `/lf/hub/list` 같은 것은 `ERROR-310` 이다.
**목록은 포털이 따로 준다(키 불필요).** `python3 scripts/lofin.py 대조` 가 그것을 불러
아래 레퍼런스 목록과 맞춰 본다. 달라졌으면 `대조 --고치기` 로 목록·칸뜻 파일을 포털에서 다시 만든다(2분쯤).
**목록에 없는 자료를 찾거나 `ERROR-310` 이 나면 먼저 `대조` 를 돌린다**(SKILL.md 「스킬 스스로 고치기」).
</HARD-GATE>

**첫째 — 이 스킬에 든 목록을 쓴다(가장 빠르다).**

`references/lofin-목록.md` 에 **146종 전부**가 분류별로 들어 있다.
각 줄에 **자료코드 · 이름 · 자료 연도 · 갱신 주기 · 검색조건 · 출력항목**이 있다.
사용자가 원하는 말(「부채」「복지비」「청사」「지방세」)로 이 파일을 훑어 후보를 고른다.

★★**분류 제목만 보고 고르지 않는다 — 같은 주제가 여러 분류에 흩어져 있다.**
「부채」가 그렇다. `부채/채무/채권` 분류(7종)만 보면 **핵심 자료를 놓친다**:

| 자료코드 | 이름 | 들어 있는 분류 |
|---|---|---|
| `ACCAM` | 회계별 지방채 잔액 | **채무현황** |
| `PRDET` | 복식부기재무현황(부채) | 재정성과/평가 |
| `JFCCJ` · `AUYDR` · `AUFDR` · `AUEAD` | 지역통합부채·부채비율 | 지역통합재정통계 |

⟹ **낱말로 파일 «전체»를 훑는다**(이름과 출력항목 둘 다). 분류 제목은 참고만 한다.

**둘째 — 칸 이름의 뜻은 `references/lofin-칸뜻.md`.** 146종 1,395칸(함정 ⑦).

**셋째 — 자치단체 이름·코드는 `references/lofin-자치단체코드.md`.**
243곳의 `laf_cd`(코드)와 이름이 시도별로 들어 있다.
★★**거르개로는 «코드»를 쓴다.** 이 자료의 자치단체명은 **앞에 시도가 붙은 한 덩어리**다 —
`경기의정부시` · `강원고성군` · `경남고성군` · 시도 본청은 `서울본청`.
⟹ **`laf_hg_nm=의정부시` 는 안 맞는다.** 이름으로 거를 거면 코드표의 표기를 그대로 쓰고,
웬만하면 `laf_cd` 를 쓴다.

**넷째 — 목록이 낡았다고 의심되면 `lofin.py 대조`.** 사람이 볼 곳은 포털의 **재정데이터개방 → 데이터셋**이고,
자료마다 「OpenAPI」 상세 화면에 요청인자와 출력값 표가 있다(스크립트가 읽는 것도 그 화면이다).
★공공데이터포털의 「요청주소 목록」 파일은 **낡은 포털 주소를 가리킨다** — 쓰지 않는다.

## 5. 거르개 이름을 알아내는 법

목록 파일의 「검색조건」은 **한글 이름**(회계연도·자치단체코드…)이라 그대로는 못 쓴다.

<HARD-GATE>
★**규칙 하나면 된다 — 「출력 칸 이름이 곧 거르개 이름」이다.**
1건만 받아서 칸 이름을 보고, 그 이름을 그대로 거르개로 쓴다.

★**목록의 「검색조건」보다 «넓게» 받아 준다**(2026-09-21 실측).
`DJAIH` 의 검색조건에는 「지역명」이 없는데 `wa_laf_hg_nm=경기` 가 실제로 먹었다
(243건 → 32건). **그러니 검색조건 칸에 없다고 포기하지 말고 한 번 넣어 본다.**
★**대신 반드시 총건수로 확인한다** — 안 먹는 이름은 오류가 아니라 «조용히 무시»되므로,
**건수가 그대로면 그 거르개는 안 먹은 것**이다(함정 ③).
</HARD-GATE>

```
python3 scripts/lofin.py RHJDKD --peek
→ 칸 이름: ['fyr','laf_cd','wa_laf_hg_nm','laf_hg_nm','smy_cntt_amt1','smy_cntt_amt2','rate']
```

자주 나오는 것(대부분의 자료가 공유한다):

| 한글 | 인자 이름 | 예 |
|---|---|---|
| 회계연도·기준년도 | `fyr` | `fyr=2024` |
| 자치단체코드 | `laf_cd` | `laf_cd=1100000` |
| 자치단체명 | `laf_hg_nm` | `laf_hg_nm=서울본청` |
| 지역(시도)코드 | `wa_laf_cd` | |
| 지역(시도)명 | `wa_laf_hg_nm` | `wa_laf_hg_nm=경기` |

## 6. 일하는 순서 — 이대로 하면 헛걸음이 없다

1. **사용자 말에서 「무슨 자료 · 어느 해 · 어디」를 뽑는다.** 안 말한 것은 묻는다(특히 **연도**).
2. `references/lofin-목록.md` 에서 **후보 자료코드**를 고른다. **분류 제목이 아니라 낱말로 파일 전체를 훑는다**(4절).
   비슷한 것이 여럿이면 이름과 출력항목으로 가른다. **당초·최종·결산**이 나뉘어 있으면 어느 것인지 정한다(함정 ⑤).
3. **`--peek` 로 1건만 받아 본다.** 여기서 총건수와 칸 이름·**칸 뜻**을 확인한다.
   - `ERROR-300` → `--fyr 2024` 를 붙여 다시.
   - `ERROR-310` → 코드 오타. 2번으로 돌아간다.
4. **거르개를 넣고 다시 `--peek`.** ★**총건수가 줄었는지 본다**(함정 ③).
5. 맞으면 **본 호출**. 많으면 `--all` 로 전 쪽을 받고 `--csv` 로 저장한다.
6. **받은 뒤 눈으로 확인한다** — 연도가 맞는지, 자치단체가 맞는지, 금액 단위가 무엇인지.
   ★**금액 단위는 대개 적혀 있지 않다**(함정 ⑧). 칸 뜻에 단위가 없으면 크기로 맞춰 보고 「추정」이라고 밝힌다.
   한 행이 회계·분야 단위로 쪼개져 있으면 `--sum`·`--by` 로 묶는다(함정 ⑥).
7. 사용자에게 줄 때 **출처를 적는다** — 「지방재정365(lofin365.go.kr), 행정안전부 · 받은 날짜」.

## 7. 스크립트 쓰는 법

`scripts/lofin.py` 는 **파이썬 기본 기능만** 쓴다(설치할 것 없음).

```bash
# 칸 이름과 총건수만 먼저 본다 (첫 걸음은 언제나 이것)
python3 scripts/lofin.py RHJDKD --peek

# 한 쪽(기본 100건)
python3 scripts/lofin.py RHJDKD --fyr 2024

# 거르개를 여러 개
python3 scripts/lofin.py DJAIH --fyr 2024 --wa_laf_hg_nm 경기

# 전체를 받아 csv 로 (엑셀에서 바로 열린다)
python3 scripts/lofin.py DJAIH --fyr 2024 --all --csv 기금현재액_2024.csv

# 시군 × 분야 세출예산 표 — 행이 「회계 × 분야 × 부문」 단위라 묶어 더한다(함정 ⑥)
# ★세출 = 정책사업 + 행정운영경비 + 재무활동 «세 칸»이다. 한 칸만 더하면 정책사업만 나온다
python3 scripts/lofin.py AIDFA --fyr 2025 --wa_laf_hg_nm 경기 \
    --sum biz_bdg_tott_amt,fin_acv_tott_amt,padm_oper_exps_tott_amt --by laf_hg_nm,fld_nm
```

`--이름 값` 은 **전부 그대로 거르개로 넘어간다.** 새 인자를 배울 필요가 없다.
`--sum 칸 --by 칸` 은 **전체 쪽을 받아** 칸을 묶음별로 더한다. `--sum` 에 쉼표로 여러 칸을 주면 한 행에서 먼저 더하고,
`--by` 도 쉼표로 여럿 준다. **덜 받았으면(총건수보다 적으면) 합을 내지 않는다.**
★**그 합은 원자료에 없는 수다** — 사용자에게 줄 때 「더한 값」이라고 밝힌다.
`--sum` 과 `--csv 파일.csv` 를 함께 주면 **`파일.csv` 에는 원자료가, `파일_합.csv` 에는 합이** 저장된다.
`--all` 은 쪽을 넘겨 가며 다 받고, 쪽 사이에 0.3초를 쉰다(상대 서버를 몰아치지 않는다).

## 8. 해 보면 감이 오는 예 셋

**「2024년 지자체별 현금성 복지비가 궁금해」**
```bash
python3 scripts/lofin.py RHJDKD --fyr 2024 --all --csv 현금성복지비_2024.csv
# 자료코드 RHJDKD = 사회보장적 수혜금(현금성복지비) 집행현황
# ★«복지비 전체»가 아니다 — 2024년 243곳 중 99곳이 0(수원시·부산본청 포함), 서울본청은 세출 33.6조에 7.3억,
#   비율(rate)은 소수 둘째 자리 밑이면 0 으로 온다(2026-09-23 실측). 무엇을 세는지 포털 설명으로 확인하지 못했다.
#   복지 예산 전체는 AIDFA 의 분야(fld_nm) 「사회복지」 를 더한다.
```

**「경기도 시군 기금 현재액 비교」**
```bash
# ★먼저 건수를 본다 — 거르개가 먹었는지 여기서 갈린다
python3 scripts/lofin.py DJAIH --fyr 2024 --peek                    # 총 243건
python3 scripts/lofin.py DJAIH --fyr 2024 --wa_laf_hg_nm 경기 --peek  # 총 32건 ← 줄었으면 먹은 것
python3 scripts/lofin.py DJAIH --fyr 2024 --wa_laf_hg_nm 경기 --all --csv 경기_기금_2024.csv
```

## 9. 하지 않을 것

- **없는 값을 지어내지 않는다.** 자료가 안 나오면 「이 자료에는 그 해가 없다」고 말한다.
  (`INFO-200` 은 오류가 아니라 **그 조건에 자료가 없다**는 뜻이다.)
- **단위를 짐작해서 바꾸지 않는다.** 원/천원/백만원은 자료마다 다르다.
- **자료를 합치거나 비율을 계산했으면 그렇게 했다고 밝힌다.** 원자료와 섞어 놓지 않는다.
- **한 번에 수십 개 자료를 훑지 않는다.** 필요한 것부터 하나씩 받는다.
