
# 열린재정 자료 받아오기

기획재정부 열린재정이 공개하는 OPEN API 를 받아 온다(몇 종인지는 `openfiscal-목록.md` 머리에 있다 — 늘고 준다).
**중앙정부 재정**이 대상이다(지방자치단체 재정은 다른 곳이다).

---


## 1. 부르는 법

```
GET https://openapi.openfiscaldata.go.kr/{서비스이름}
    ?Key={인증키}&Type=json&pIndex={쪽번호}&pSize={쪽당건수}&{거르개...}
```

서비스이름은 **영문**이다 — `GovernmentDebtYear`(국가채무) · `GovernmentDebtMonth`(월별 국가채무) ·
`VWFOEM2`(월별 지출운용상황) …. `references/openfiscal-목록.md` 에 전부가 있다.

---

## 2. ★★이 API 의 함정 — 모르면 「서버가 죽었다」로 오해한다

전부 2026-09-21 에 실제로 부딪혀 확인한 것이다.

### ① ★**「누가 부르는지」로 막는다** — 가장 크게 헤매는 자리

프로그램 기본 표식(User-Agent)으로 부르면 **자료 대신 「서비스에 접속할 수 없습니다」 오류 화면**을 준다.
**브라우저 표식을 달면 정상 자료**가 온다.

⟹ 주소도 인자도 맞는데 오류 화면이 오면 **서버 장애로 단정하지 말고 표식부터 확인한다.**
(스크립트가 붙여 준다. 직접 부를 때는 `User-Agent` 헤더를 꼭 단다.)

### ② 성공이 **HTTP 201** 이다

200 이 아니다. 게다가 **`Content-Type` 은 `text/html`** 인데 내용물은 JSON 이다.
**상태코드나 Content-Type 으로 성패를 가르면 틀린다.**

### ③ ★**JSON 을 «두 번» 풀어야 한다**

겉이 한 번 더 문자열로 싸여 있다. 한 번만 풀면 **그냥 긴 글자 덩어리**가 나온다.
(스크립트가 두 번 푼다.)

### ④ 서비스이름의 «이상한 철자»는 오타가 아니다

`ForeignExpenditureBudgget5` 처럼 **`Budgget`** 으로 적힌 것이 있다. **상대 쪽 이름이 실제로 그렇다.**
고쳐서 부르면 `ERROR-310`(해당 서비스 없음)이 온다 — **목록에 적힌 철자를 그대로 쓴다.**(실측 확인)

### ⑤ 실패·빈결과는 **모양이 다르다**

성공은 `{"서비스이름": [...]}`, 실패와 「자료 없음」은 `{"RESULT": {...}}` 다.
같은 방식으로 파싱하면 깨진다.

### ⑥ ★★**금액 단위가 목록에 없고, 서비스마다 다르다**

조원·억원·천원·원이 섞여 있다. **같은 「기금」 묶음 안에서도** `OPFI162` 는 조원, `OPFI163` 은 억원이다.
아래는 2026-09-23 에 **알려진 총액과 크기를 맞춰 보고 정한 것**이다 — 공식 표기가 아니라 **추정**이다.

| 서비스 | 금액 칸 | 단위(추정) | 맞춰 본 값 |
|---|---|---|---|
| `GovernmentDebtYear` | `GOD_SUM_AMT` 등 | 조원 | 2025 국가채무 1,305.2 |
| `OPFI162` 기금성격별 · `OPFI165` 분야별 재원배분 | `SUM_AMT` | 조원 | 2025 분야 합 684.1 |
| `OPFI163` 사업성기금 · `OPFI167` 국고보조사업 추이 | `AMT` · `SUM_EP_AMT` | 억원 | 2026 국고보조 1,054,538 = 105.5조 |
| `TotalExpenditure5` 등 세부사업 예산 | `…_KCUR_AMT` | 천원 | 2025 총지출(예산+기금) 합 673,301,580,117 = 673.3조 |
| `DepartRevenExpenSettle` 소관별 결산 | `EP_AMT` 등 | 원 | 복지부 2024 지출 72,594,733,598,360 = 72.6조 |

★`GovernmentDebtYear` 에는 **그해 값이 결산인지 추경·전망인지 가르는 칸이 없다.** 최근 해는 결산이 아닐 수 있다고 밝힌다.

⟹ **표에 없는 서비스는 단위를 단정하지 않는다.** 알려진 총액 하나와 크기를 맞춰 보고,
사용자에게는 「단위 표기가 없어 크기로 추정」이라고 함께 적는다.

### ⑦ ★**이름만 보고 예산인지 결산인지 판단하지 않는다 — 구분 칸을 본다**

`OPFI165`(16대분야별재원배분)는 이름이 예산처럼 읽히지만 **결산만 준다**(2023~2025 전부 「결산」).
요약형(`OPFI…`) 서비스는 대개 **`DIV_NM` · `STL_BDG_DIV_NM` · `BDG_STL_DIV_NM`** 칸에
「결산」·「본예산」이 적혀 온다. **`--peek` 로 그 칸부터 본다.**

## 3. 응답 코드

| 코드 | 뜻 | 할 일 |
|---|---|---|
| `INFO-000` | 정상 | — |
| `INFO-200` | 해당 자료 없음 | 오류가 아니다. 거르개를 넓힌다 |
| `ERROR-290` | 인증키가 유효하지 않음 | 키 확인. 승인 전이면 기다린다 |
| `ERROR-300` | 필수 값 누락 | **그 서비스의 ★필수 인자**를 목록에서 찾아 넣는다 |
| `ERROR-310` | 해당 서비스 없음 | 서비스이름 오타 |
| `ERROR-336` | 1회 1,000건 초과 | `pSize` 를 1000 이하로 |

---

## 4. 어떤 자료가 있나

`references/openfiscal-목록.md` 에 분류별로 있고, 종마다 이렇게 적혀 있다.

- **서비스이름** (주소에 넣는 것)
- **검색인자** — 이름과 뜻, **★필수 표시까지**
- **출력칸** — 돌아오는 자료의 칸 이름

★**많은 서비스가 필수 인자를 갖고 있다.** 그러니 **먼저 목록에서 필수 인자(★필수)를 확인하고 부른다.**
★목록은 받은 날의 것이다 — 목록에 없거나 `ERROR-310` 이면 `python3 scripts/openfiscal.py 대조` 를 먼저 돌린다(2026-09-23 대조에서 104종 → 198종, 1종 없어짐).
안 그러면 `ERROR-300` 을 보고 헤맨다.

큰 갈래 — **국가채무 · 예산(세입/세출) · 결산 · 집행 · 재정지출(유형별·회계기금별) ·
통합재정통계(GFS) · 월간재정동향 · 국가재정운용계획 · 연기금투자풀**.

자주 쓰는 것:

| 서비스이름 | 무엇 | 필수 인자 |
|---|---|---|
| `GovernmentDebtYear` | 국가채무(D1), 연도별 29개 연도 | 없음 |
| `GovernmentDebtMonth` | 월별 국가채무 | 없음(`OJ_YY` 로 해를 좁힌다) |
| `VWFOEM2` | 월별 지출운용상황 | 있음 — 목록 확인 |
| `TotalExpenditure5` | 세부사업 예산편성현황(총지출) — **분야별 총지출·세출예산은 이것을 더한다**(`BDG_FND_DIV_CD` 0 이면 예산+기금 = 총지출, 1 이면 예산만) | `FSCL_YY` · `BDG_FND_DIV_CD`(0 전체·1 예산·5 기금) · `ANEXP_INQ_STND_CD`(1 총지출·2 세출순계) |
| `DepartRevenExpenSettle` | 소관(부처)별 세입·세출 결산 | `FSCL_YY` |

**자주 나오는 코드 값** — 목록 파일에는 「★필수」만 적히고 값은 안 적힌다.

| 인자 | 값 |
|---|---|
| `BDG_FND_DIV_CD` 예산기금구분 | 0 전체 · 1 예산 · 5 기금 |
| `ANEXP_INQ_STND_CD` 세출조회기준 | 1 총지출 · 2 세출순계 |
| `REVN_INQ_STND_CD` 세입조회기준 | 값을 확인하지 못했다 — `--peek` 로 1 을 넣어 보고, 결과를 보고 판단한다 |

★**요약형과 상세형** — `OPFI…` 는 **이미 묶은 요약**(행 수십 개, 대개 결산)이고,
영문 이름 서비스는 **세부사업 단위 상세**(행 수천 개)다. 요약에 원하는 묶음이 있으면 그것을 쓰고,
없으면 상세를 받아 `--sum`·`--by` 로 묶는다(6절).

## 5. 일하는 순서

1. **사용자 말에서 「무슨 자료 · 어느 해」를 뽑는다.** 빠진 것은 묻는다.
2. `references/openfiscal-목록.md` 에서 **서비스이름과 필수 인자**를 확인한다.
3. **`--peek` 로 1건만 받아 본다** — 총건수와 칸 이름을 여기서 본다.
   - `ERROR-300` → 목록의 ★필수 인자를 넣는다.
   - 오류 «화면»이 오면 → 함정 ①. 표식 문제다(스크립트를 쓰면 안 생긴다).
4. 거르개를 넣고 다시 `--peek` 해서 **총건수가 줄었는지 확인한다.**
5. 맞으면 `--all --csv` 로 받아 저장한다.
6. **받은 뒤 눈으로 확인한다** — 해가 맞는지, **예산인지 결산인지**(함정 ⑦), **단위가 무엇인지**(함정 ⑥).
7. 출처를 적는다 — 「열린재정(openfiscaldata.go.kr), 기획재정부 · 받은 날짜」.

---

## 6. 스크립트

```bash
# 칸 이름과 총건수 먼저 (첫 걸음은 언제나 이것)
python3 scripts/openfiscal.py GovernmentDebtYear --peek

# 전체를 csv 로
python3 scripts/openfiscal.py GovernmentDebtYear --all --csv 국가채무.csv

# 거르개를 붙여서
python3 scripts/openfiscal.py GovernmentDebtMonth --OJ_YY 2025 --all --csv 월별채무_2025.csv

# 「2025 중앙정부 분야별 총지출」 — 바로 주는 서비스가 없어 세부사업을 분야별로 더한다
# ★BDG_FND_DIV_CD 0 = 예산+기금 = «총지출». «세출예산»(예산만)이면 1 을 준다. 두 말을 섞지 않는다
python3 scripts/openfiscal.py TotalExpenditure5 --FSCL_YY 2025 --BDG_FND_DIV_CD 0 \
    --ANEXP_INQ_STND_CD 1 --sum Y_YY_DFN_MEDI_KCUR_AMT --by FLD_NM
# → 9,435건을 받아 분야별 합을 찍는다. 합 673,301,580,117 — 천원으로 보면 673.3조(단위는 크기로 맞춘 추정). 국회확정 금액 칸이다
```

`--sum 칸 --by 칸` 은 **전체 쪽을 받아** 칸을 묶음별로 더한다(`--by` 는 쉼표로 여럿).
★**그 합은 원자료에 없는 수다** — 사용자에게 줄 때 「세부사업을 더한 값」이라고 밝힌다.

`--이름 값` 은 **전부 그대로 거르개로 넘어간다.** 브라우저 표식·두 번 풀기·쪽 넘기기는 스크립트가 처리한다.

---

## 7. 하지 않을 것

- **없는 값을 지어내지 않는다.** 빈 결과는 「그 조건에 자료가 없다」고 말한다.
- **단위를 추정했으면 추정이라고 밝힌다.** 서비스마다 조원·억원·천원·원이 다르다(함정 ⑥). 표기 없이 환산한 수를 확정값처럼 쓰지 않는다.
- **중앙정부 자료다.** 지방자치단체 재정을 물으면 **다른 자료(지방재정365)** 라고 알려 준다.
- **연도 표기를 확인한다** — 같은 「2025」가 예산 기준인지 결산 기준인지 자료마다 다르다.
